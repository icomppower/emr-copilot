# Fluid UI research — EMR Copilot demo (2026-10-14)

Constraint: one static `index.html`, D3 7 from cdnjs, no build. One pick per pattern.

| Pattern | Pick | Why |
|---|---|---|
| D3 collapsible tree | Observable "collapsible tree" pattern: `d3.hierarchy(data, d => d.collapsed ? null : d.children)`, entering nodes/links start at the parent's previous position (`x0/y0`), exiting ones shrink into the nearest visible ancestor, then stash `x0/y0` | Already the shape of the existing `draw()`; keeps object constancy when folding. Focus mode is just a class (`dim`/`fade`) on the same join, not a second layout. |
| Animated expand/collapse | `display:grid; grid-template-rows: 0fr → 1fr` with an `overflow:hidden; min-height:0` child, toggled by a class + `aria-expanded` on a real `<button>` | Works in every evergreen browser today. `interpolate-size: allow-keywords` (animate to `height:auto`) is still Chromium-only; `<details>` can't animate its close without JS and we need programmatic open/close (auto-open newest log group, collapse all). Dock sections additionally animate `flex-grow` so open panels share the dock height. |
| Fluid layout | Root `font-size: clamp(13px, .45vw + 8.4px, 19px)`, everything else in `rem`/`clamp()`; app shell `height: 100dvh`; `@media` for the page shell (dock side vs bottom vs phone), `@container` for panels (stage, dock, queue, log, drawer) | Media queries for root layout and container queries for components is the common split. `dvh` survives mobile toolbars. One root clamp scales the whole UI from a 400px phone to a 1920px projector with no fixed px heights. |
| Resizable split pane | Hand-rolled: `pointerdown` + `setPointerCapture` on the splitter, write a CSS variable (`--dockW` / `--dockH`) on the grid, save to `localStorage` on `pointerup`; `role="separator"`, `aria-orientation`, `aria-valuenow`, arrow keys / Home / End, double-click resets | Pointer capture keeps the drag alive outside the handle without body listeners. A CSS var means one style write per move; the graph refits from a `ResizeObserver`. No library needed. |
| View Transitions | Same-document `document.startViewTransition(fn)`, feature-detected; skipped when `prefers-reduced-motion: reduce`; `::view-transition-*` animations off under that media query too. Used for discrete layout jumps (dock show/hide, presenter mode) with `view-transition-name` on stage and dock | The fallback is just calling `fn()`. Continuous changes (splitter drag, D3 tree, accordions) keep their own transitions; VT is only for jumps CSS can't tween. |

Sources: [Observable collapsible tree](https://observablehq.com/notebook-kit/ex/d3/collapsible-tree) · [Chrome: animate to height auto](https://developer.chrome.com/docs/css-ui/animate-to-height-auto) · [Modern CSS: container query units + fluid type](https://moderncss.dev/container-query-units-and-fluid-typography/) · [Resizable split pane from scratch](https://theoslater.is-a.dev/blog/building-a-resizable-split-pane-from-scratch) · [web.dev: view transitions for SPAs](https://web.dev/learn/css/view-transitions-spas)
